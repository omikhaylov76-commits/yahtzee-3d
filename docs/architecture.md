# Architecture — Yahtzee 3D

> Как строим. Решения зафиксированы в ADR (`docs/adr/`). Стек выбран на ШАГе 3.

## Стек

- **Язык:** TypeScript (строгий режим).
- **Сборка/dev:** Vite.
- **UI:** React (экраны, таблица счёта, меню, состояния).
- **3D:** Three.js через **React Three Fiber (R3F)** + helpers **drei** (тени, окружение,
  постобработка, блики).
- **Физика костей:** **Rapier** (`@react-three/rapier`) — WASM, быстрая, детерминируемая.
- **Звук:** **Howler.js** за нашим интерфейсом `SoundEngine`.
- **Состояние UI:** Zustand (лёгкий стор как «мост» между ядром и React/3D).
- **Хранилище:** `localStorage` за интерфейсом `GameStorage`.
- **Тесты:** Vitest (ядро правил/счёта покрываем модульными тестами).
- **Линт/формат:** ESLint + Prettier.

Подробности выбора — ADR 0002.

## Границы модулей (ядро / отрисовка / звук / сеть / хранилище)

Главный принцип: **ядро игры не знает ни про 3D, ни про React, ни про звук, ни про сеть.**
Оно чистое и детерминированное. Всё остальное — слои вокруг, общающиеся через контракты.

```
            ┌──────────────────────────────────────────────┐
            │                    UI (React)                 │
            │  экраны, таблица счёта, контролы, состояния   │
            └───────▲───────────────┬──────────────────────┘
                    │ читает state   │ шлёт actions
                    │                ▼
┌─────────────┐   ┌─────────────────────────────┐   ┌──────────────┐
│  render3d   │◄──┤        Transport (контракт) ├──►│   sound      │
│ Three/R3F/  │   │  Local (сейчас) / Network    │   │ SoundEngine  │
│ Rapier;     │   │  (заглушка-точка под сервер) │   │ (Howler)     │
│ показывает  │   └──────────────▲──────────────┘   └──────────────┘
│ кости       │                  │ применяет action
└─────────────┘                  ▼
                       ┌─────────────────────┐     ┌──────────────┐
                       │   core (чистый TS)  │     │ GameStorage  │
                       │ правила, счёт, RNG, │◄───►│ (localStorage)│
                       │ reducer, события    │     │ автосохранение│
                       └─────────────────────┘     └──────────────┘
```

### core/ — ядро игры (чистый TS, без DOM/3D/React)

- Типы: `GameState`, `Player`, `ScoreCard`, `Category`, `DiceState` (5 костей: значение +
  «зафиксирована»), `RollPhase` (номер броска 1..3).
- Чистые функции счёта: `scoreCategory`, `upperSum`, `totalScore` (13 категорий, верхний
  бонус +35 при ≥63, бонусные Yahtzee +100, джокер).
- **Reducer:** `reduce(state, action) => { state, events[] }` — единственный способ менять
  состояние. Детерминированно. Возвращает доменные события для слоёв (звук/сочность).
- **RNG ядра:** значения костей определяет ЯДРО (сидируемый ГПСЧ), а не физика — ради
  детерминизма и будущей сети (ADR 0004). 3D лишь красиво показывает заранее известный
  результат.

### Actions (вход в ядро)

`NEW_GAME(config)`, `ROLL`, `TOGGLE_HOLD(dieIndex)`, `SCORE(category)`.
Передача хода и конец игры выводятся ядром автоматически после `SCORE`.

### Domain events (выход из ядра, для звука/сочности)

`dice:rolled`, `dice:settled`, `die:held`, `die:released`, `score:written`,
`action:denied`, `combo:yahtzee`, `turn:changed`, `game:over`.
Слои отрисовки и звука подписываются и реагируют (звук, частицы, анимации). Ядро их только
испускает — не вызывает звук напрямую.

**Кто что испускает (уточнение, аудит ШАГ 4 п.3):**

- _Логические_ события испускает **ядро** в `reduce`: `dice:rolled`, `die:held`,
  `die:released`, `score:written`, `action:denied`, `combo:yahtzee`, `turn:changed`,
  `game:over`.
- _Тайминговое_ `dice:settled` испускает **render3d**, когда физика реально успокоилась
  (момент для звука «стук/остановка» и разблокировки UI). Без 3D (fallback) его эмитит сразу
  слой-заглушка отрисовки.

### Transport — контракт «действие/состояние» (точка под сеть)

```ts
interface Transport {
  getState(): GameState;
  dispatch(action: Action): void; // применить действие
  subscribe(cb: (s: GameState, ev: DomainEvent[]) => void): () => void;
}
```

- **LocalTransport** (сейчас): синхронно прогоняет `reduce` локально, шлёт state+events
  подписчикам, сохраняет через `GameStorage`.
- **NetworkTransport** (потом, заглушка-точка): тот же интерфейс, но `dispatch` уходит на
  сервер, а state приходит обратно. Ядро и UI не меняются. Сейчас — только пустой класс-
  заглушка с TODO, чтобы было видно точку расширения (ADR 0003).

### render3d/ — отрисовка (R3F + Rapier)

- Сцена, камера, свет, материалы стола и костей; физический бросок (тумбл) с приземлением
  на значения, заданные ядром; считывание «успокоились» → `dice:settled`.
- Частицы/блик на `combo:yahtzee`. Читает состояние, не меняет правила.

### sound/ — звук за интерфейсом

```ts
interface SoundEngine {
  play(event: SoundEvent): void;
  setMuted(m: boolean): void;
  setVolume(v: number): void; // 0..1
  startAmbient(): void;
  stopAmbient(): void;
}
```

- **Реализация (F5): процедурно на Web Audio за интерфейсом `SoundEngine`** (ADR 0006), без
  Howler/ассетов. Реальные CC0-сэмплы — позже, подменяются за тем же интерфейсом. Маппинг
  доменных событий → звуки (`sound/soundMap.ts`); настройки (mute/volume/ambient) живут в
  сторе и сохраняются в localStorage.
- **Лицензия ассетов:** когда добавим живые сэмплы — фиксировать источник + лицензию (CC0)
  в `public/sounds/CREDITS.md` и ADR. Кандидаты: archive.org CC0, freesound CC0, kenney.nl.
- **Контраст костей (аудит ШАГ 4 п.4):** на тёмном фоне Auros материал кубиков — светлый,
  точки-пипсы чёткие; проверять читаемость и контраст (доступность) при работе над F4/F6.

### storage/ — хранилище за интерфейсом

```ts
interface GameStorage {
  save(state: GameState): void;
  load(): GameState | null;
  clear(): void;
}
```

- Реализация — `localStorage` (ключ версионируется, чтобы не падать на старом формате).
  Автосохранение после каждого значимого действия; восстановление при старте; «Новая игра»
  очищает (ADR 0005).

## Контракты и события

- Единственная мутация состояния — через `reduce` (ядро). UI шлёт `Action` в `Transport`.
- Слои не зовут друг друга напрямую: связь через `Transport.subscribe` (state) и доменные
  события (реакции). Это держит границы и упрощает будущую сеть.
- Значения костей — всегда из ядра; 3D их визуализирует, не порождает.

## Стратегия заглушек (сеть)

- Контракт `Transport` готов с самого начала; используется `LocalTransport`.
- `NetworkTransport` присутствует как пустой класс с TODO и комментарием «точка под сервер»
  — реализуется в Вехе 2 без изменения ядра/UI.
- В `GameState` заранее заложены поля под будущую сеть: `gameId?`, `seed` (для общего RNG),
  `players[].id`. Это даёт патч-расширение без миграции (ADR 0003).

## Безопасность (соразмерно: чистый фронт)

- Бэкенда и секретов на старте нет.
- Единственный пользовательский ввод — имена игроков: длина ограничена, при выводе
  экранируются (React по умолчанию экранирует — не использовать `dangerouslySetInnerHTML`).
- `GameStorage` читает только свой ключ; при повреждённых данных — безопасный фолбэк на
  новую игру, без падения.

## Производительность

- Цель 60fps: число костей мало (5), физика Rapier дешёвая; следим за лишними
  React-перерисовками (3D-стейт держим вне React-рендера, через ref/Zustand-селекторы).
- Тяжёлые ассеты (звуки, окружение) грузим с прелоадером (состояние «загрузка» из spec).
- Fallback без WebGL: играбельный 2D-режим костей (минимальная отрисовка), чтобы не белый
  экран (состояние «ошибка» из spec).
