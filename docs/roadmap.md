## Backlog / хвосты

- **ЗВУК НЕ ФИНАЛЬНЫЙ.** Сейчас стоит временный процедурный звук (Web Audio, ADR 0006) — это
  заглушка. Заказчик ПОЗЖЕ доделает звук полноценно: подберёт и подключит качественные реальные
  сэмплы (стук костей, клики, фанфары и т.д. — Kenney / freesound, CC0) за тем же интерфейсом
  `SoundEngine`. Архитектура специально оставлена открытой под замену звука без переписывания.
  Это запланированное будущее улучшение — дверь оставлена открытой.
- reduced-motion + 3D: РЕШЕНО (F6.3 + правка по фидбэку). 3D-бросок — игровая механика, а не
  декор: кости катятся ВСЕГДА, независимо от системного reduce-motion. Reduce-motion гасит только
  декоративное (фейды экранов, частицы Yahtzee, пульс очков, glow). Ранняя гипотеза «мгновенный
  бросок при reduce» отменена: пользователь с включённым reduce хочет видеть бросок.
- Физику падения костей «попилить» позже: дошлифовать кувырок в воздухе/качение по столу и
  естественность доводки на грань (детерминированная доводка предсказателя — местами можно
  натуральнее). Базовое поведение принято заказчиком (F4).
- Бандл ~3 МБ (Three.js + Rapier WASM) — РЕШЕНО в F6.4: 3D-арена вынесена в ленивый чанк, старто-
  вый JS ~174 КБ. Сам 3D-чанк остаётся крупным (Three+Rapier WASM ~2.9 МБ) — грузится по требова-
  нию; дальнейшее дробление three/rapier — при желании позже, выгода невелика.
- a11y: фиксация костей в 3D — только указателем (клик), без клавиатуры. 2D-fallback (Die как
  button) с клавиатуры работает; sr-only статус значений есть. Полноценный keyboard-hold для 3D —
  отдельная фича (перенесено из F6.3).
- 60fps: проверка в DevTools Performance — на заказчике (ленивая загрузка на рантайм-fps не влияет).
- 5 npm-уязвимостей в транзитивных dev-зависимостях — проверить `npm audit`, закрыть без
  ломающих обновлений.
- Джокер: строгое принуждение бокса (сначала верхний по достоинству) не enforced в ядре —
  запись свободная, счёт корректный. Возможное уточнение правил позже.
