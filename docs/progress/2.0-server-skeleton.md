## План под-шага 2.0.a — Серверная сборка + fastify health-check

**Цель.** Завести ВТОРУЮ сборочную цепочку для сервера (ADR-0014/architecture «Сборка
сервера»), которой раньше не было, и поднять минимальный `fastify`-сервер с `/health`.
Критерий: `npm run dev:server` поднимает сервер, `curl /health` → `200 {status:'ok'}`;
`npm run build:server` собирает запускаемый prod-бандл. Клиент НЕ затрагиваем.

**Почему это отдельный под-шаг.** Текущий `tsconfig.json` заточен под браузер (`lib: DOM`,
`moduleResolution: bundler`, `noEmit`, `include: ['src']`) — серверу не годится. Нужна
своя цепочка; это не «папка», а инфраструктура. В 2.0.a сервер СЕБЯ-достаточен (ещё НЕ
импортирует `core`) — так изолируем «работает ли сборка/раннер» от «импортируется ли core»
(последнее — риск ESM-без-расширений, решаем в 2.0.b).

**Зависимости (из согласованного набора, architecture.md; ставлю ПОСЛЕ «ок»):**

- runtime: `fastify`
- dev: `tsx` (раннер dev), `tsup` (prod-эмит, esbuild), `@types/node`
  (`socket.io`, `drizzle`, `concurrently` и пр. — в 2.0.b и позже, по мере надобности.)

**Файлы — ТРОНЕМ:**

- NEW `server/index.ts` — `fastify`-приложение; маршрут `GET /health` → `{ status: 'ok' }`;
  `listen` на `host 0.0.0.0`, `port = process.env.PORT ?? 3001` (Railway задаёт PORT/0.0.0.0).
- NEW `tsconfig.server.json` — typecheck сервера: `module: ESNext`, `moduleResolution: bundler`
  (как у клиента — чтобы позже импортировать `core` без расширений), `lib: ES2022`,
  `types: ['node']`, без `DOM`/`jsx`, `noEmit: true`, `include: ['server']`.
- NEW `tsup.config.ts` — сборка `server/index.ts` → `dist-server/` (format esm, target node20, clean).
- NEW `.nvmrc` — версия Node (`24`).
- EDIT `package.json` — добавить зависимости; скрипты `dev:server` (`tsx watch server/index.ts`),
  `build:server` (`tsup`), `typecheck:server` (`tsc -p tsconfig.server.json`); поле `engines.node` (`>=20`).
- EDIT `eslint.config.js` — добавить в `ignores` `dist-server`; отдельный блок для `server/**/*.ts`
  с `globals.node` (иначе `process` = no-undef под browser-globals; и без react-плагинов).
- EDIT `.gitignore` — добавить `dist-server`.

**Файлы — НЕ трогаем:** весь `src/*` (клиент/ядро), клиентский `tsconfig.json`, `vite.config.ts`,
поведение клиента. Сервер пока самостоятельный, ядро не импортирует.

**Контракты/данные:** не меняем. **Railway:** в 2.0.a НЕ деплоим (локальный запуск); деплой и
переменные — в 2.0.b (там и твои ручные действия на Railway).

**Граничные случаи:**

- `PORT`/`HOST` из окружения (Railway) с локальными дефолтами (3001 / 0.0.0.0).
- ESM-проект (`"type":"module"`) — серверные файлы ESM; tsx/tsup это держат.
- Lint сервера: node-globals, без react-правил; prod-бандл `dist-server` игнорируется lint/git.
- Изоляция: сервер не тянет `core` (это 2.0.b), чтобы отделить риск ESM-импорта ядра.

**Как проверим (живьём, с артефактами):**

1. `npm run typecheck:server` — вывод (типы сервера ок).
2. `npm run lint` — чисто (серверный блок eslint работает, `process` не ругается).
3. `npm run dev:server` → `curl -s -i localhost:3001/health` → `200`, тело `{"status":"ok"}` (артефакт).
4. `npm run build:server` → `node dist-server/index.js` → снова `curl /health` 200 (prod-бандл запускается).
5. Регрессия клиента: `npm run lint`/`npm run test` зелёные (клиент не затронут).
