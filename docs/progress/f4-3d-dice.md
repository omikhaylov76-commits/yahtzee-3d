# f4-3d-dice (фича в roadmap: Веха 1 → F4. 3D-кости и физический бросок)

Последний коммит по фиче: ffdeb7d (Nudge + гарантия плоской укладки + тактильная физика)
Файлы под-шага (тронем): уточняется в плане под-шага (см. список ниже по под-шагам)

## Решения (согласовано на старте F4, ответ заказчика «делай как лучше»)

1. **Физика — Rapier.** Ставим `@react-three/rapier` (закладывалось архитектурой и ADR 0002).
   Зависимость согласована делегированием решения.
2. **Значения — из ядра (ADR 0004).** Физика красиво тумблит, но в момент покоя кость
   доворачивается гранью с уже известным из ядра значением к камере. Физика НЕ порождает
   значения.
3. **Гейт UI на время полёта.** Пока кости летят — Roll/запись/hold недоступны. Для этого в
   стор-мост (`gameStore.ts`) добавляем флаг `settling: boolean` (НЕ в ядро — это слой
   отрисовки/моста). Снимается по `dice:settled`, который эмитит render3d при покое.
4. **Fallback без WebGL.** 2D-кости (`Die`/`DieFace`/`Dice`) НЕ удаляем — оставляем как
   запасной путь отрисовки, если WebGL/3D недоступны (требование architecture.md, без белого
   экрана).

## Контракт со слоями (не нарушаем)

- Ядро (`core/`), `transport/`, `storage/` — НЕ трогаем.
- Значения костей всегда из `state.dice[i].value`; 3D их визуализирует.
- `dice:settled` — событие слоя render3d (не ядра), как зафиксировано в architecture.md.

### Текущий статус выбора способа (F4.3)

Заказчику вариант `reveal` (e84f96f) **почти нравится**: бросок хороший, значения почти не
перепрыгивают. Осталась ОДНА доработка, если вернёмся к нему:

> **Точки должны быть чёткими/чёрными ВСЁ время — без серого проявления в полёте.**

**Спайк A (F4.3a) — ПРОЙДЕН (3/3, `determinism.spike.test.ts`):** Rapier детерминирован
(одинаковый старт → бит-в-бит та же грань), кости ложатся плоско на одну грань (предсказание
надёжно), `takeSnapshot/restoreSnapshot` воспроизводит бросок. ⇒ вариант A технически
осуществим на движке. Остаточный риск — точное совпадение «живого» R3F-мира с headless-
предсказателем (дрейф зеркала); подстрахуемся рантайм-сверкой «предсказано vs факт» в F4.3b.

Решение по способу: пробуем **вариант A** (предрасчёт броска + переразметка граней —
честный, точки always-on, ноль коррекции, идеален под авторитетную сеть). Сначала спайк
детерминизма повтора в нашем стеке (`@react-three/rapier` / Rapier). Если A выходит красиво
— берём A. Если спайк/A не выходит — возвращаемся к `reveal` (e84f96f) и допиливаем
доработку выше (точки чёткие всегда).

### Сеть (подтверждено аудитом транспорта)

Ядро/контракты к серверу с БД и кабинетами готовы без переписывания: ядро чистое и на seed,
`GameState` сериализуем, `Transport` изолирует «локально/сеть», есть `gameId?`/`players[].id`.
Подправить позже (патч, не переписывание): `Transport` синхронный → асинхронные апдейты/
отклонение действий сервером (флаг connection/pending в сторе, как `settling`); seed/значения
авторитетны на сервере (физика косметическая — это усиление ADR-0004).
