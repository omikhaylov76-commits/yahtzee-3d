## Под-шаги

- [x] **1. Безопасный `unseed-leaderboard` (MAJOR-1, офлайн-скрипт)** (ea2d0fa) — `server/scripts/unseed-leaderboard.ts`.
      Было: удалял «осиротевшие» партии (`matches.id NOT IN (SELECT match_id FROM match_players)`) ПОСЛЕ сноса
      seat'ов seed-игроков → реальная партия, смешанная с синтетиком, удалилась бы целиком (потеря истории).
      Стало: чисто-seed партии считаем ЯВНО (все участники — seed; гость/реальный игрок → партия не трогается),
      seed-юзеров сносим только без оставшихся ссылок (FK). Добавлен `--dry-run` (read-only).
      CHECK ✓: typecheck:server, eslint ., живой `--dry-run` против прод-БД (8 чисто-seed / 0 смешанных).

- [x] **2. Watchdog на `pending` в NetworkTransport (MAJOR-2, в пути деплоя)** (6543eb3) — `src/transport/NetworkTransport.ts`.
      Было: нет таймаута на `pendingActionId` → если `state` потерян БЕЗ разрыва сокета (`enter()` не вызван),
      кнопки залипают навсегда (в 1-на-1 нового состояния без своего хода не будет; лечилось reload).
      Стало: таймер-сторож (`watchdogMs`=15с, инъектируется): по таймауту снимает залипший pending + уведомляет
      подписчиков → UI разблокируется; сервер сверит на следующем действии (версии монотонны, ADR-0013). Хелперы
      `armPending`/`clearPending`; без изменения протокола/интерфейса сокета.
      CHECK ✓: eslint ., 269 тестов (+4 watchdog: таймаут/state/reset/denied), tsc --noEmit; независимый
      code-reviewer — чисто (проверены пути сброса pending, утечка таймера, гонки, совместимость net.ts).
