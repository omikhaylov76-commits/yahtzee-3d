## Решения (зафиксированы 2026-06-20)

- **dev-БД = одна Railway-база** на старте (и dev, и prod; делегировано заказчиком). Разделим при росте.
- **PostgreSQL создан** на Railway (`Postgres ● Online`, проект yahtzee-3d). Подключение:
  - рантайм сервера на Railway → внутренний `DATABASE_URL` (приватная сеть, reference `${{Postgres.DATABASE_URL}}`);
  - локально (миграции/dev с моей машины) → `DATABASE_PUBLIC_URL` (TCP-прокси) в `.env`.
- **Крючки монетизации** в таблице users: `tier` + `entitlements` (пустые полочки, ADR no-pay-to-win) —
  чтобы потом не мигрировать БД под выбранную модель.

## Хвосты / спящие баги

- **Прод подключён к БД** (2.3.b): в yahtzee-3d задан `DATABASE_URL` — ВНУТРЕННИЙ адрес Postgres прямым
  значением (через CLI, не reference). Вход end-to-end в проде записал аккаунт ✓. _При смене пароля
  Postgres обновить вручную (или перевести на reference `${{Postgres.DATABASE_URL}}` в Railway dashboard)._
- **Google app — режим Testing/Published:** owner (заказчик) входит и в Testing; для ДРУЗЕЙ нужно
  «Publish app» (любой Google) ИЛИ добавить их почты в Test users. Проверить перед тестом с людьми.
- **Ротация Client Secret:** Secret проходил через чат — после пилота сделать Reset secret в Google Cloud.
- **SSL для публичного подключения** не понадобился (Railway TCP-proxy принял без `sslmode`); если на
  другой машине drizzle-kit/pg потребует SSL — добавить `?sslmode=require` в `.env`.

3. Проба подключения: node-скрипт — `SELECT` из `users` (0 строк) + проверка наличия таблиц `users`,

## План под-шага 2.3.b — Вход через Google (делегировано: «как лучше/технически обоснованно»)

**Решения (зафиксированы 2026-06-20):**

- Authorization Code flow, `google-auth-library@^10`. Client ID получен; Secret — в env (заказчик).
- **state (CSRF):** server-side `Map<state, expiresAt>` + TTL 10 мин, сверка+удаление на callback. Без
  cookie/jose до 2.3.c (single-process — достаточно; рестарт во время входа = повтор, приемлемо).
- **redirect_uri:** из env `GOOGLE_REDIRECT_URI` (dev `http://localhost:3001/auth/google/callback`,
  prod `https://yahtzee-3d-production.up.railway.app/auth/google/callback`). Должен совпадать с Google client.
- **Аккаунт:** `findOrCreateUser` — identity по (provider, sub); нет → создать users+identities в транзакции.
- **Граница:** 2.3.b → «аккаунт в БД». Постоянная сессия (cookie/jose) — 2.3.c. Callback пока отдаёт
  временную страницу «вошёл как …».

**Разбивка:** b-1 (сервер: AuthProvider+google+routes+upsert+прод-линковка БД) → b-2 (клиент: кнопка входа).

### b-1 — серверный OAuth-flow ✓ (8507426; end-to-end вход ждёт Secret заказчика)

**Файлы — ТРОНЕМ:**

- NEW `server/platform/auth/AuthProvider.ts` — контракт (`getAuthUrl(state)`, `exchangeCode(code)` →

## План под-шага 2.3.c — Сессии (постоянная залогиненность)

**Решения (делегировано «как лучше»):**

- `jose` (JWT, HS256, подпись `SESSION_SECRET`) + `@fastify/cookie`. Сессия — httpOnly cookie
  (`SameSite=Lax`: работает и dev :5173↔:3001 (один сайт), и prod same-origin; `Secure` только prod).
- TTL access-токена + отзыв через `tokenVersion` (users) — «выйти со всех устройств».
- WS: socket.io `withCredentials` → cookie в handshake → сервер опознаёт залогиненного игрока.
- `SESSION_SECRET` — новый секрет (генерирую), в `.env` + Railway.

**Разбивка:** c-1 серверная сессия → c-2 клиент (статус/выход/возврат) → c-3 WS-токен → c-4 zod-валидация.
