## Решения (зафиксированы 2026-06-20)

- **dev-БД = одна Railway-база** на старте (и dev, и prod; делегировано заказчиком). Разделим при росте.
- **PostgreSQL создан** на Railway (`Postgres ● Online`, проект yahtzee-3d). Подключение:
  - рантайм сервера на Railway → внутренний `DATABASE_URL` (приватная сеть, reference `${{Postgres.DATABASE_URL}}`);
  - локально (миграции/dev с моей машины) → `DATABASE_PUBLIC_URL` (TCP-прокси) в `.env`.
- **Крючки монетизации** в таблице users: `tier` + `entitlements` (пустые полочки, ADR no-pay-to-win) —
  чтобы потом не мигрировать БД под выбранную модель.

## Хвосты / спящие баги

- **Прод-сервер ещё НЕ подключён к БД:** reference `DATABASE_URL=${{Postgres.DATABASE_URL}}` в
  yahtzee-3d сервисе зададим в 2.3.b (при первом реальном использовании БД) — чтобы не дёргать живой
  прод лишним redeploy'ем в 2.3.a. БД работает локально (миграции/проба) через публичный URL.
- **SSL для публичного подключения** не понадобился (Railway TCP-proxy принял без `sslmode`); если на
  другой машине drizzle-kit/pg потребует SSL — добавить `?sslmode=require` в `.env`.

**Зависимости (согласованы в architecture.md; ставлю по «ок»):**

- NEW `drizzle.config.ts` — `dialect: 'postgresql'`, `schema: server/platform/db/schema.ts`, `out: 'drizzle'`,
  `dbCredentials.url = DATABASE_URL`.
- NEW `drizzle/` — сгенерированная SQL-миграция (drizzle-kit generate).
- EDIT `package.json` — зависимости + скрипты `db:generate` (`drizzle-kit generate`), `db:migrate`

- Railway (yahtzee-3d сервис): добавить `DATABASE_URL` = reference `${{Postgres.DATABASE_URL}}` (внутренний).
- EDIT `eslint.config.js`/`tsconfig.server.json` — покрыть `drizzle.config.ts` (корень) и `server/platform/db`,
  игнор `drizzle/` сгенерированного при необходимости.

**Файлы — НЕ трогаем:** `core/*`, игровой поток/экраны, `realtime.ts`/`rooms.ts` (БД пока НЕ интегрируем
в игру — это 2.3.e), клиент.

**Безопасность:** `DATABASE_URL` — СЕКРЕТ: только `.env` (gitignore) + Railway env; НИКОГДА в код/git/логи/чат.

**Граничные случаи:**

- `gen_random_uuid()` — встроен в Postgres 13+ (Railway новее) — extension не нужен; проверить на прогоне.
- Публичное подключение Railway proxy может требовать SSL (`?sslmode=require`) — учесть в pg Pool/конфиге.
- Внутренний `DATABASE_URL` (railway.internal) работает ТОЛЬКО внутри Railway → локально только публичный.
- drizzle-kit `generate` (offline, без БД) ≠ `migrate` (нужна БД) — разделить шаги.

**Как проверим (живьём, с артефактами):**

1. `npm run db:generate` → появляется SQL-миграция в `drizzle/` (offline).
2. `npm run db:migrate` (DATABASE_URL=public) → таблицы создаются на Railway-БД.
3. Проба подключения: node-скрипт — `SELECT` из `users` (0 строк) + проверка наличия таблиц `users`,
   `identities` (артефакт: список таблиц / успешный запрос).
4. Регрессия: `build:all`, `lint`, `typecheck:server`, `npm test` (185) — зелёные.

## План под-шага 2.3.b — Вход через Google (делегировано: «как лучше/технически обоснованно»)

**Решения (зафиксированы 2026-06-20):**

- Authorization Code flow, `google-auth-library@^10`. Client ID получен; Secret — в env (заказчик).
- **state (CSRF):** server-side `Map<state, expiresAt>` + TTL 10 мин, сверка+удаление на callback. Без
  cookie/jose до 2.3.c (single-process — достаточно; рестарт во время входа = повтор, приемлемо).
- **redirect_uri:** из env `GOOGLE_REDIRECT_URI` (dev `http://localhost:3001/auth/google/callback`,
  prod `https://yahtzee-3d-production.up.railway.app/auth/google/callback`). Должен совпадать с Google client.
- **Аккаунт:** `findOrCreateUser` — identity по (provider, sub); нет → создать users+identities в транзакции.
- **Граница:** 2.3.b → «аккаунт в БД». Постоянная сессия (cookie/jose) — 2.3.c. Callback пока отдаёт
  временную страницу «вошёл как …».

**Разбивка:** b-1 (сервер: AuthProvider+google+routes+upsert+прод-линковка БД) → b-2 (клиент: кнопка входа).

### b-1 — серверный OAuth-flow

**Файлы — ТРОНЕМ:**

- NEW `server/platform/auth/AuthProvider.ts` — контракт (`getAuthUrl(state)`, `exchangeCode(code)` →
  `AuthUserInfo {provider, externalId, email, displayName, avatarUrl}`).
- NEW `server/platform/auth/google.ts` — `createGoogleAuthProvider` (OAuth2Client: generateAuthUrl
  scope openid/email/profile; getToken; verifyIdToken aud=clientId → payload sub/email/name/picture).
- NEW `server/platform/auth/users.ts` — `findOrCreateUser(info)` через `db` (drizzle), транзакция.
- NEW `server/platform/auth/routes.ts` — `registerAuth(app, provider)`: GET `/auth/google/start`
  (state→store→redirect) + GET `/auth/google/callback` (проверка state → exchangeCode → findOrCreateUser
  → временная страница). Ошибки: state-mismatch/no-code/google-fail → 400.
- EDIT `server/index.ts` — собрать GoogleAuthProvider из env, `registerAuth`. БД-импорт только если есть
  GOOGLE\_\* (вход опционален — без ключей сервер поднимается, как сейчас прод-пилот).
- EDIT `.env` (локально) + `.env.example` — `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI`.
- Railway (прод): задать `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI`, `DATABASE_URL`
  (reference `${{Postgres.DATABASE_URL}}`) — при деплое b (закрывает отложенную линковку из 2.3.a).

**Как проверим:**

- Я (технически, без secret): `/auth/google/start` → 302 на `accounts.google.com` с client_id/scope/state
  (curl -I); callback без state/с чужим state → 400; типы/линт/сборка/185 тестов.
- Заказчик (вживую, с secret + его email в Test users): пройти вход Google → в БД появляется его
  `users`+`identities` (проверю запросом). Я в Google войти не могу — финальный шаг на заказчике.
