# 2.4-leaderboard (фича в roadmap: Веха 2 → 2.4 Лидерборд + реконнект-арбитраж + полировка)

Последний коммит по фиче: 5e4e502 (2.4.a-2) — под-шаг a (лидерборд) закрыт; ПРОД: 2.4.a задеплоена + лидерборд засеян синтетикой (railway up 340baca, 2026-06-21)
Файлы под-шага (тронем): уточняется в плане каждого под-шага (микрофазы ниже)

> Решения (заказчик 2026-06-21, ADR-0018): лидерборд — публичная таблица; **сортировка по СУММЕ
> очков**; строка богатая: ник+аватар · очки(сумма) · лучшая игра(max) · сыграно · победы. Зачёт —
> только честные СЕТЕВЫЕ партии с ≥2 РАЗНЫМИ зарегистрированными (`matches.registeredCount>=2`),
> гостевые/брошенные/локальные — нет. Удалённые аккаунты в витрине не показываем. Анти-фарм — мягко
> для пилота (риск сговора задокументирован, строгая защита → backlog). Приватно: только ник+аватар+
> метрики. Новый экран из меню + ссылка из кабинета.
>
> Данные ГОТОВЫ (2.3.d): `matches`/`match_players` пишутся; лидерборд = запрос+экран, без миграции.
> Реванш (бывш. 2.4.b) — уже сделан в 2.5. Кросс-секционное требование (англ-строки, a11y, состояния
> загрузка/пусто/ошибка, мобайл) — планка КАЖДОГО нового экрана.

## Под-шаги

- [x] **a. Лидерборд** — дроблю на a-1/a-2:
  - [x] a-1 (9720fe6) (сервер): чистый агрегат `leaderboard(limit)` — `SUM(total)`/`MAX(total)`/`COUNT`/
        `COUNT filter isWinner` по `match_players` ⋈ `matches` (registeredCount≥2) ⋈ `users`
        (deletedAt IS NULL, nickname NOT NULL), GROUP BY userId, ORDER BY сумма DESC, LIMIT N.
        Контракт `LeaderboardRow {nickname, avatarUrl, points, best, played, wins}`; HTTP `GET
/leaderboard` (публичный, без auth). Чистый `computeLeaderboardRow`/mapping + юнит-тест.
        Файлы: server/platform/stats/leaderboard.ts (новый), server/index.ts, shared/protocol.ts (тип) (+ тест).
  - [x] a-2 (5e4e502) (клиент): экран `LeaderboardScreen` + fetch-хук (как `useOpenTables`, но одноразовый +
        кнопка refresh; `GET /leaderboard` через vite-proxy в dev); `view:'leaderboard'` + роутер;
        вход из меню («Leaderboard») + ссылка из кабинета; состояния загрузка/пусто/ошибка; a11y
        (таблица: `<table>`/`scope`, клавиатура, sr-friendly) + мобайл (горизонтальная прокрутка/
        сжатие колонок). Файлы: src/state/leaderboard.ts (новый), src/ui/screens/LeaderboardScreen.tsx
        (новый), src/state/uiStore.ts, src/ui/screens/MenuScreen.tsx, CabinetScreen.tsx, App.tsx,
        theme.css, vite.config.ts (+ тест).

- [ ] **c. Полный реконнект-арбитраж** (ADR-0010): **reconnect-токен на место** (непубличный, вкл.
      гостя — закроет хвост 32-битного публичного `playerId` из аудита 2.5); серверный таймер

      ответ `room-not-found/expired` при исчезнувшей комнате. Удержание роли хозяина при реконнекте
      в приватном лобби (хвост 2.2). Файлы: realtime.ts, seating.ts, protocol.ts, schemas.ts, клиент-транспорт.

- [ ] **d. Финальная полировка** состояний/адаптива/a11y сетевых экранов (остаток сверх кросс-секции);
      нота игрокам «рестарт/деплой сервера может прервать партию» (ADR-0009). Файлы: по месту.

## Хвосты / спящие баги (учесть/отложить)

- **Строгий анти-фарм лидерборда** (кулдаун зачёта повторных встреч пары, детект сговора,
  уникальность по IP/identity) — backlog, ДО широкого запуска (ADR-0018; вектор из аудита 2.5).
- **Сортировка/пагинация лидерборда** — старт: топ-N по сумме очков. Кликабельные колонки/страницы — позже.
- **`/leaderboard` без rate-limit/кэша** (публичный GET, как `/tables`/`/status`) — общий хвост лимитов.
- **Заметка гостю «результат не в рейтинге»** (перенос из 2.2.b) — показать на экране входа/итогов гостю.
- Реклейм-токен (c) закрывает: 32-битный `playerId` (аудит 2.5), удержание хозяина (2.2), «застрявший
  ход отсутствующего» (2.1/2.2) — свести при реализации c.
