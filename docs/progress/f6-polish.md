# f6-polish (фича в roadmap: Веха 1 → F6. Сочность и полировка)

Последний коммит по фиче: нет
Файлы под-шага (тронем): по под-шагам ниже (каждый под-шаг = свой коммит)

Решения заказчика (старт F6):

- Объём: ПОЛНЫЙ — все 4 под-шага (визуал + reduced-motion/a11y + производительность). Веха 1 закрывается полностью.
- Празднование Yahtzee/победы: СДЕРЖАННО-ДОРОГО — аккуратный всплеск частиц + мягкий glow, без китча.
- Без новых зависимостей: частицы и анимации — чистый CSS/DOM (без animation-библиотек). Согласование на любую новую зависимость.
- npm audit (5 транзитивных уязвимостей) — НЕ часть F6, остаётся отдельным пунктом backlog.

Сквозной принцип: каждая анимация уважает `prefers-reduced-motion` — при reduce анимации
выключаются/упрощаются, функциональность не страдает. Слои не путаем: сочность реагирует на
доменные события ядра (`combo:yahtzee`, `score:written`, `turn:changed`, `game:over`), в правила
не лезет.

## Под-шаги:

- [~] 1. Микроанимации UI — переходы экранов + пульс записи очков + подсветка смены игрока
  - Тронем: `src/ui/theme.css` (keyframes + reduced-motion guard), `src/App.tsx` (fade-in
    экрана при смене), `src/ui/components/CategoryRow.tsx` (пульс ячейки при `score:written`),
    `src/ui/components/ScoreTable.tsx` (подсветка текущего игрока при `turn:changed`),
    новый `src/ui/useReducedMotion.ts` (реактивный хук вместо разовой функции).
  - НЕ тронем: `src/core/*`, `src/render3d/*`, `src/sound/*`, transport/storage.
  - Граничные: монтирование/размонтирование экранов (fade только на вход, без сложной
    оркестрации выхода — без библиотек); запись очков 0 тоже пульсирует; reduce → без анимаций.
  - Проверка: build + lint; dev — пройти ход, увидеть пульс при записи и плавную смену экрана;
    в DevTools включить reduce-motion → анимации выключены, игра работает.

- [ ] 2. Празднование Yahtzee и победы — частицы + glow (сдержанно)
  - Тронем: новый `src/ui/components/Celebration.tsx` (слушает события из стора, рендерит
    всплеск частиц + glow-оверлей; reduce → мягкая вспышка без частиц), `src/App.tsx`
    (глобальный монтаж `<Celebration/>`), `src/ui/theme.css` (стили/keyframes частиц и glow).
  - НЕ тронем: `src/core/*`, `src/render3d/*`, `src/sound/*` (звук Yahtzee уже есть, F5).
  - Граничные: несколько Yahtzee подряд (перезапуск анимации по ключу события); победа на
    `game:over`; частицы не блокируют клики (`pointer-events:none`); reduce → без частиц.
  - Проверка: build + lint; dev — собрать Yahtzee (или временный сид) → увидеть всплеск; дойти
    до конца игры → праздничный акцент на экране победы; reduce → тихая вспышка.

- [ ] 3. Reduced-motion в 3D + финальный a11y-проход
  - Тронем: `src/ui/capabilities.ts` (реактивность reduce — согласовать с хуком из п.1),
    `src/render3d/DiceCanvas.tsx` и/или `src/render3d/DiceField.tsx` и/или
    `src/render3d/constants.ts` (при reduce — мгновенная укладка костей на финальные значения
    без тумбла/реплея, бэклог-пункт F4→F6), `src/ui/theme.css` (`:focus-visible` состояния).
  - a11y-проход: фокус-кольца на кнопках/ячейках, клавиатура (Roll/Nudge/запись/hold),
    aria/sr-only достаточность для 3D-канваса (статус уже есть в GameScreen).
  - НЕ тронем: `src/core/*`, `src/sound/*`, transport/storage.
  - Граничные: reduce включён во время полёта костей; смена reduce на лету; hold в 3D с
    клавиатуры (canvas pointer-only — проверить, что sr-status + 2D-путь покрывают).
  - Проверка: build + lint; dev с reduce — бросок мгновенный, значения верные; Tab-обход всех
    контролов с видимым фокусом.

- [ ] 4. Производительность — ленивая загрузка 3D (Three/Rapier) + проверка 60fps
  - Тронем: `src/ui/screens/GameScreen.tsx` (`React.lazy` + `Suspense` для `DiceCanvas`),
    `src/render3d/DiceCanvas.tsx` (default-экспорт/обёртка под lazy), при необходимости
    `vite.config.ts` (`manualChunks` для three/rapier).
  - НЕ тронем: `src/core/*`, `src/sound/*`, правила/счёт.
  - Цель: бандл ~3 МБ (Three+Rapier WASM) уезжает в отдельный чанк, грузится лениво; стартовый
    JS заметно меньше. Fallback без WebGL (2D) не тянет 3D-чанк.
  - Граничные: Suspense-фолбэк при загрузке арены; 2D-путь без WebGL не импортирует Three;
    реплей-приземление не ломается из-за code-split.
  - Проверка: build → показать размеры чанков (стартовый JS ↓, 3D в отдельном файле); dev —
    арена грузится через фолбэк и работает; 60fps в DevTools Performance на броске.
