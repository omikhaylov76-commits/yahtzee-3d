# ADR 0016 — Стол переживает партию, старт по готовности и реванш (только открытые/дежурные)

- Статус: accepted
- Дата: 2026-06-20

## Контекст

Заказчик хочет, помимо приватных комнат по коду, **открытые** и постоянные («дежурные»)
столы, куда заходят без кода и где партия запускается «по согласию» игроков, а после конца
стол снова ждёт игроков (реванш). Двойной независимый аудит существующего кода
(`realtime.ts`/`seating.ts`/`rooms.ts`/`gameStore.ts`/`App.tsx`) вскрыл:

- `room.game` ставится один раз при старте и **никогда не сбрасывается**; клиентский роутер
  показывает экран победителя, пока есть состояние игры; обнулить состояние на сетевом пути
  сейчас можно ТОЛЬКО разрывом сокета (`goLocal`/`dispose`). То есть «комната переживает
  партию» в коде ОТСУТСТВУЕТ — это не галочка, а механизм клиент+сервер+протокол.
- Унификация «старт по готовности во ВСЕХ комнатах» = регрессия рабочей приватной 2.2 (снос
  host-Start с каскадом по UI/стору и падением тестов) + «вечный код-пропуск» (после сброса в
  лобби `room:already-started` перестаёт защищать утёкший код).
- В реваншном лобби впервые появляются ЖИВЫЕ игроки, держащие место → reclaim-гейт по
  `room.game` ломается (дубль места/выкид при блипе сети).
- В безхозяйном открытом столе чистое «все готовы» уязвимо: один залипший игрок блокирует
  старт навсегда.

## Решение

1. **Сужаем до открытых/дежурных (`open`/`persistent`).** Приватные комнаты по коду НЕ трогаем:
   там остаётся host-Start (2.2 работает). «Стол переживает партию», ready-up и реванш — только
   для `open`/`persistent`. Это снимает регрессию 2.2 и «вечный код-пропуск».
2. **Механизм «партия → лобби» (фундамент, делается ПЕРВЫМ).** На `game:over` для
   `open`/`persistent` сервер НЕ убивает комнату: `room.game=null`, чистит мёртвые места
   (`socketId===null`), сбрасывает `seat.ready=false`, рассылает новое сообщение возврата в
   лобби. КЛИЕНТ по нему обнуляет публичное состояние и версию (`stateVersion=0`), выставляет
   `state=null`, `connectedIds=null`, **НЕ роняя** сокет/`playerId`/комнату → роутер показывает
   лобби. Запись итога партии (`recordMatch`) — СТРОГО до сброса (иначе залогиненные запишутся
   как гости, т.к. сброс меняет `room.seats`).
3. **Старт по готовности (ready-up) для `open`/`persistent`.** Сообщение «я готов» (toggle),
   поле `ready` в месте и в снимке лобби. Сервер при изменении пересчитывает «все ПРИСУТСТВУЮЩИЕ
   готовы И их ≥2» → авто-старт (идемпотентно: повторный ready при идущей партии — no-op).
   **Предохранитель (вариант А):** место, занятое игроком, который не подтверждает готовность
   ~60 с, **авто-освобождается** — залипший не блокирует стол. Новый зашедший НЕ сбрасывает
   чужие `ready` (просто делает «все готовы» ложным до своей готовности).
4. **Реванш = «остались за столом + снова готовы».** «Play again» — сетевое действие (как
   `start`/`kick` в `OnlineSession`), НЕ локальный `newGame` (он no-op в сети). Соло/локаль не
   трогаем.
5. **Reclaim в реваншном лобби.** Гейт reclaim расширяем: место в `open`/`persistent` лобби,
   занятое известным `playerId`, при блипе сети возвращается тому же игроку (а не fresh-join с
   дублем/`room:full`).

## Альтернативы

- **Ready-up + реванш во ВСЕХ комнатах (вкл. приватные):** единообразно, но регрессия рабочей
  2.2 + «вечный код-пропуск» + лишние развилки. Отклонено по аудиту.
- **Сброс в лобби обычным `state` с понижением версии:** транспорт отбрасывает снимок не-новее
  текущего — «понизить» версию нельзя. Отклонено: нужен явный сигнал возврата в лобби.
- **Чистое «все готовы» без предохранителя:** залипший блокирует открытый стол навсегда.
  Отклонено в пользу авто-освобождения молчащего места.

## Последствия

- ➕ Открытые/дежурные столы получают естественный старт «по согласию» и реванш; приватные 2.2
  не ломаются.
- ➕ Один механизм «партия→лобби» обслуживает и реванш, и постоянные столы (не дублируем);
  закрывает заявленное в ADR-0014 «реванш в сети».
- ➖ Фундамент — это клиент+сервер+протокол (новое сообщение, обнуление `state`, reclaim-в-лобби,
  bump версии протокола), не «мелочь». Делается первым под-шагом и разбит на сервер/клиент.
- ➖ Два пути старта (host-Start для приватных, ready-up для `open`/`persistent`) — осознанная
  цена за отсутствие регрессии; они не пересекаются по типу комнаты.
- ➖ Деплой с bump протокола рвёт активные партии (как любой рестарт, ADR-0009) — штатно для пилота.
