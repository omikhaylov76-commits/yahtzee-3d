# ADR 0011 — Сеть как переиспользуемая платформа; игра как модуль (задел под портал)

- Статус: accepted
- Дата: 2026-06-18

## Контекст

В перспективе заказчик хочет ПОРТАЛ с несколькими играми (Yahtzee, шашки, карты, морской бой):
общий вход, общий кабинет, общие комнаты, общий/пер-игровой лидерборд. Каждая игра — отдельный
«модуль игры» на единой сетевой платформе. Сам портал — будущая Веха 4+, сейчас НЕ строим.

При этом нельзя оверинжинирить: строить абстрактный фреймворк «на 10 игр» вслепую — вредно.
Нужна сетевая часть Yahtzee, сделанная ЧИСТО, с ясными границами, чтобы её МОЖНО было выделить
в самостоятельный пакет под вторую игру — не загоняя решения в угол.

## Решение

Разделяем код по двум зонам с явной границей; граница проходит по уже существующему контракту
«действие → состояние» (`Transport`, ADR-0003).

- **Платформа (переиспользуемое, игро-НЕзависимое):** сервер (Node + Socket.IO), соединения,
  комнаты (создание/вход по коду, хозяин, список игроков, статусы), авторизация (Google + гость),
  сессии, кабинеты (имя, аватар) — общие для всех игр, инфраструктура лидерборда (механизм
  общий, очки пер-игровые), реконнект/пауза, авторитетный цикл «принять действие → проверить →
  прогнать reduce игры → разослать состояние+события», хранение ОБОБЩЁННОГО итога партии.
- **Игра (игро-специфичное):** правила и счёт (`core`/`reduce`), типы `Action`/`GameState`/
  `DomainEvent`, 3D-отрисовка, звук, и маппинг конца партии в обобщённый «результат» (кто играл,
  кто победил, очки).

Граница — контракт **`GameModule`**, который игра реализует, а платформа вызывает «вслепую»:

```ts
interface GameModule<State, PublicState, Action, Event, Result> {
  // playerIds задаёт ПЛАТФОРМА (сессии/аккаунты), не сама игра — стабильные id мест:
  createInitialState(playerIds: string[], config, seed): State;
  reduce(state: State, action: Action): { state: State; events: Event[] };
  isPlayersTurn(state: State, playerId: string): boolean; // авторизация действия
  isGameOver(state: State): boolean;
  getResult(state: State): Result; // обобщённый итог для статистики/лидерборда
  toPublicState(state: State, forPlayerId?: string): PublicState; // СНЯТЬ секреты (seed/rng) перед рассылкой
}
```

`toPublicState` — ключевой для анти-чита (ADR-0009): только игра знает, что в её состоянии
секретно (у Yahtzee — `seed`/`rng`), поэтому проекция публичного состояния живёт в модуле игры,
а платформа рассылает клиентам именно её. `createInitialState` принимает id мест ОТ платформы.

Новая игра «получает сеть бесплатно», реализовав `GameModule` (и свой клиент-рендер) — комнаты,
аккаунты, лидерборд, реконнект даёт платформа. Yahtzee — ПЕРВЫЙ модуль на этой платформе.
Реализация для Yahtzee — это аккуратные ДОБАВЛЕНИЯ к существующему `core/` (внешние id, чистые
функции, проекция публичного состояния), а не переписывание правил/счёта.

**Анти-оверинжиниринг (явное правило):** реализуем в `GameModule` и платформе ТОЛЬКО то, что
нужно Yahtzee. Не добавляем «крючков на будущие игры» без надобности. Цель — чистый шов, а не
готовый мульти-игровой фреймворк. Фактическое выделение в отдельный публикуемый пакет и портал
(меню игр) — рефакторинг/Веха 4+, когда появится вторая игра; платить за это сейчас не нужно.

## Альтернативы

- **Жёстко вшить сеть в Yahtzee** (без границы платформа/игра): быстрее сейчас, но вторую игру
  не подключить без распутывания — отклонено (видение портала известно заранее, шов дешёвый).
- **Сразу строить абстрактную мульти-игровую платформу/монорепо с пакетами:** оверинжиниринг
  под несуществующие игры — отклонено (риск «угадать не тот контракт» до второй игры).

## Последствия

- ➕ Граница совпадает с уже существующим `Transport` (ADR-0003) — шов почти бесплатен.
- ➕ Вторая игра подключается реализацией `GameModule`, переиспользуя сеть/аккаунты/лидерборд.
- ➕ Чистые границы полезны и одной игре (тестируемость, читаемость), даже если портала не будет.
- ➖ Чуть больше дисциплины в раскладке кода (платформа отдельно от игры) уже в Вехе 2.
- ➖ Контракт `GameModule` может уточниться при появлении 2-й игры — допустимо (его реализует
  пока только Yahtzee, менять дёшево).
