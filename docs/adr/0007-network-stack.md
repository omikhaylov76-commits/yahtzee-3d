# ADR 0007 — Сетевой стек: Node + Socket.IO + PostgreSQL на Railway

- Статус: accepted
- Дата: 2026-06-18

## Контекст

Веха 2 — реальная сетевая игра нескольких людей с разных устройств в одной комнате. Нужен
сервер (хостинг Railway, есть аккаунт заказчика), технология реального времени для ходов/
бросков и база данных для аккаунтов/статистики/лидерборда. Клиент уже на TypeScript/React,
а ядро игры (`core/`) — чистый TS, детерминированное, авторитет по значениям костей у ядра
(ADR-0004). Хотим стартовать просто, но иметь задел до ~300–500 одновременных игроков без
переписывания.

## Решение

- **Сервер:** Node.js на TypeScript. Это позволяет переиспользовать `core/` как общий пакет
  (одно ядро правил/счёта на клиенте и сервере, без дублирования) — см. ADR-0009.
- **Реальное время:** Socket.IO (надстройка над WebSocket: авто-reconnect, комнаты, события).
  Игровой обмен идёт по сокетам + состояние комнаты в памяти сервера. Малые сообщения
  (одно действие / одно состояние).
- **База данных:** PostgreSQL (управляемая Railway). ТОЛЬКО для аккаунтов, статистики,
  лидерборда — вне горячего игрового пути. Записи редкие (итог партии, вход), чтения
  кэшируемы (лидерборд/профиль). БД узким местом не будет by design.
- **Хостинг:** Railway (сервер + Postgres). Секреты — только в переменных окружения Railway.
- **Масштабирование позже:** комнаты независимы; при росте — несколько копий сервера +
  Redis как общая «шина» между ними. Закладываем как возможность, НЕ делаем на старте
  (без оверинжиниринга).

## Альтернативы

- **Colyseus** (игровой фреймворк комнат): берёт на себя комнаты/синхронизацию/реконнект/
  масштабирование, меньше своего кода. Отклонён на старте: выше порог входа и привязка к
  фреймворку; наш случай (2–4 игрока, авторитетный reduce) простыми сокетами закрывается
  прозрачнее. Возможен ввод позже без смены языка/хостинга, если «комнатной» рутины станет много.
- **BaaS (Supabase)**: аккаунты/БД/realtime почти из коробки, но их realtime заточен под
  синхронизацию данных, а не под авторитетную игровую комнату — авторитетного судью всё равно
  строим отдельно, получается два мира + привязка вне Railway. Отклонён: менее стройно именно
  из-за авторитетных костей.

## Последствия

- ➕ Один язык (TS) и один репозиторий клиент+сервер; ядро переиспользуется напрямую.
- ➕ Socket.IO сам разбирается с капризными сетями (мобильный интернет) и reconnect.
- ➕ БД вне realtime-пути → дёшево и не упирается при росте.
- ➕ Дешёвый старт (см. прикидку тарифов в roadmap), масштабирование — отдельный поздний шаг.
- ➖ Комнаты/очередь ходов/хранение партии пишем сами (простой, но наш код).
- ➖ Появляется бэкенд (раньше был чистый фронт): новые заботы — секреты, деплой, БД.
