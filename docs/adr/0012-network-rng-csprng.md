# ADR 0012 — Сетевой RNG: значения костей из CSPRNG на сервере

- Статус: accepted
- Дата: 2026-06-18

## Контекст

Анти-чит Вехи 2 (ADR-0009) опирался на «секретный `seed` на сервере + рассылка публичного
состояния без `seed`/`rng`». Аудит вскрыл дыру: `core/rng.ts` — это `mulberry32`,
**НЕ криптостойкий** ГПСЧ. Его состояние — одно 32-битное число, шаг тривиально обратим. А
значения костей по природе игры ВИДНЫ всем игрокам. По нескольким опубликованным броскам
состояние генератора восстанавливается, и все будущие броски (свои и чужих) становятся
предсказуемыми. Убрать `seed`/`rng` из рассылаемого состояния НЕОБХОДИМО, но НЕДОСТАТОЧНО:
секретность seed бесполезна, если seed восстановим из выходов. Принцип ADR-0004 (значения —
от ядра, физика лишь показывает) остаётся; меняется ИСТОЧНИК значений в сетевом режиме.

## Решение

- **В сетевом режиме значения бросков генерирует СЕРВЕР из криптостойкого источника**
  (`crypto.randomInt` / `crypto.getRandomValues`), а не из `mulberry32(seed)`. По выходам CSPRNG
  предсказать следующий бросок нельзя.
- **Ядро принимает значения броска ИЗВНЕ (инъекция).** Ядро остаётся авторитетным по ПРАВИЛАМ
  и счёту (ADR-0004), но конкретные числа костей сетевого `ROLL` ему передаёт сервер. Это
  чистое добавление: путь «применить бросок с заданными значениями» (а не «ядро само бросило
  по seed»). `core` не переписываем — расширяем точкой инъекции.
- **`mulberry32`/`seed`/`rng` остаются для ЛОКАЛЬНОГО режима и тестов** (детерминизм, воспроизводимость,
  существующие 34 теста). В локальной игре предсказуемость не важна (один человек/устройство).
- **Рассылаемое публичное состояние (`toPublicState`) всё равно НЕ содержит `seed`/`rng`** — и как
  поля, и потому что сетевые числа не выводятся из них. Двойная защита.
- Поле `seed` по умолчанию `= 1` (`game.ts`) — в сетевом пути дефолт ЗАПРЕЩЁН; локальный seed
  берётся из случайного источника транспортом (как сейчас в `LocalTransport`).

## Альтернативы

- **Оставить `mulberry32` + просто прятать `seed`/`rng`:** ложная безопасность (см. контекст) —
  отклонено.
- **Заменить ядровый ГПСЧ на криптостойкий и в локальном режиме:** ломает детерминизм/тесты,
  не нужно локально — отклонено. Источник значений разный по режиму, правила/счёт — едины.

## Последствия

- ➕ Реальный анти-чит: будущие броски непредсказуемы даже при наблюдении прошлых.
- ➕ Ядро остаётся чистым и тестируемым; добавляется лишь точка инъекции значений.
- ➕ Локальный детерминизм и тесты не страдают.
- ➖ Путь броска в `core` должен принимать готовые значения (аккуратное расширение типов/reduce).
- ➖ Два источника значений (локальный seed vs серверный CSPRNG) — описать явно в `GameModule`/обвязке.
