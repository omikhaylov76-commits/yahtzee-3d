# ADR 0004 — Значения костей определяет ядро (физика только показывает)

- Статус: accepted
- Дата: 2026-06-17

## Контекст

3D-физика выглядит реалистично, но недетерминирована (зависит от частоты кадров, железа).
Если значения костей «считывать с физики», результат нельзя воспроизвести и нельзя
синхронизировать по сети (разные клиенты увидят разное).

## Решение

Авторитет по значениям костей — у ядра: сидируемый ГПСЧ в `core` генерирует результат
броска. 3D-сцена проигрывает красивый физический тумбл и **приземляет кости на уже
известные ядру значения** (ориентируем финальные грани под целевой результат). Слой
отрисовки сообщает только «кости успокоились» (`dice:settled`) для тайминга звука/UI.

## Альтернативы

- Физика решает значения, ядро считывает: реалистичнее «по-честному», но недетерминировано,
  ломает тесты и будущую сеть — отклонено.

## Последствия

- ➕ Ядро чистое, тестируемое; одинаковый результат на всех клиентах (готово к сети по seed).
- ➕ Можно честно тестировать счёт без запуска 3D.
- ➖ Нужен приём «приземлить кость на заданную грань» в render3d (решаемо: подбор ориентации
  после остановки или направленный бросок). Допустимая инженерная задача.
