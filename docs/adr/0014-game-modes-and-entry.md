# ADR 0014 — Режимы игры, точка входа и разведение локального/сетевого хранилища

- Статус: accepted
- Дата: 2026-06-18

## Контекст

Веха 1 — это весь UI: роутер экранов выбирает экран ТОЛЬКО по состоянию игры (`App.tsx`:
нет состояния → Start, `over` → Winner, иначе Game). Нет понятия «режим», нет меню, `StartScreen`
жёстко «Local · hotseat». Веха 2 добавляет сетевой путь (вход → кабинет → комната), но аудит
показал: он нигде не стыкуется с существующим входом. Без явной развилки игрок не понимает, во
что играет, и ломаются три вещи Вехи 1: автосохранение (localStorage) против сетевой партии,
кнопка «Play again» (локальный `newGame`) в сетевой партии, и обещанный spec соло-«рекорд»,
который сейчас не сохраняется НИГДЕ.

## Решение

- **Явная точка входа (меню/режим):** «Играть локально (hotseat / соло на одном устройстве)» vs
  «Играть по сети». Локальный путь сохраняет дух spec «сел и играешь» (без аккаунта). Сетевой путь
  ведёт во вход (Google/гость) → лобби/комнаты. Сохраняем оба, не ломая Веху 1.
- **`Transport` выбирается режимом:** локально — `LocalTransport` (синхронно, как сейчас); сеть —
  `NetworkTransport`. Роутер экранов учитывает режим (а не только состояние игры): нужны экраны
  меню, лобби, кабинета, лидерборда поверх существующих Start/Game/Winner.
- **Хранилище разведено по режиму.** `GameStorage` (localStorage, автосохранение/восстановление,
  ADR-0005) обслуживает ТОЛЬКО локальные партии. Сетевая партия живёт на сервере (ADR-0009);
  localStorage её НЕ сохраняет и НЕ восстанавливает (иначе перезагрузка вкладки поднимет устаревшую
  локальную копию поверх сетевого реконнекта). Реконнект сетевой партии — по протоколу (ADR-0013).
- **«Play again»/реванш — по режиму.** Локально — как сейчас (`newGame` через `NEW_GAME`). В сети —
  реванш на сервере (комната жива после `game:over`, новая партия через `createInitialState`,
  ADR-0009/0013). WinnerScreen разводит кнопку по режиму СРАЗУ, не дожидаясь поздней фичи лидерборда.
- **Соло-рекорд (обещание spec) — локальный персональный рекорд.** Соло «на рекорд» сохраняется
  ЛОКАЛЬНО (в `GameStorage`/отдельном ключе): лучший личный итог между сессиями, без аккаунта и без
  сети. Сетевая статистика/лидерборд (ADR-0008) — отдельно, для зарегистрированных. Так закрывается
  противоречие «spec обещает рекорд, а он нигде не хранится».
- **Соло = всегда локально** (1 игрок). Сетевая комната требует ≥2 игроков.

## Альтернативы

- **Убрать обещание соло-рекорда из spec:** проще, но обедняет одиночный режим, заявленный в spec —
  отклонено (локальный рекорд дёшев).
- **Единое хранилище для локальной и сетевой партии:** прямой конфликт источников правды
  (localStorage vs сервер) — отклонено.

## Последствия

- ➕ Игрок ясно выбирает режим; Веха 1 (hotseat/соло) не ломается.
- ➕ Нет конфликта localStorage ↔ сетевая партия; «Play again» корректен в обоих режимах.
- ➕ Соло-рекорд выполняет обещание spec без аккаунтов.
- ➖ Роутер экранов и навигация усложняются (меню/лобби/кабинет поверх Start/Game/Winner) — это
  новая UI-работа, заложить в Веху 2, а не «допилить потом».
- ➖ spec обновить: соло-рекорд = локальный персональный (уточнение к сценарию 11/критериям).
