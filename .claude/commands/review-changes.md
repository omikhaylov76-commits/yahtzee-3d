Проверь изменения, сделанные в текущей фиче, прежде чем я закоммичу.

Фокус проверки (опционально): $ARGUMENTS

Сделай:
1. Покажи и проанализируй дельту: `git diff` (и `git status`, чтобы ничего лишнего не попало).
2. Прогони проверки командами из `CLAUDE.md`: линт и тесты. Сообщи результат честно.
3. Пройдись по чек-листу:
   - соответствие плану и конвенциям (CLAUDE.md, ADR);
   - необработанные ошибки/граничные случаи;
   - безопасность (секреты, валидация ввода);
   - не затронуты ли посторонние файлы;
   - покрыты ли новые ветки логики тестами.
4. Дай вывод: 🔴 блокеры / 🟡 стоит поправить / 🟢 на заметку.
5. ШАГ FIX: есть 🔴 блокеры -> НЕ коммить. Предложи их починить, по моему «ок» поправь и
   вернись к п.1 (перепроверь дельту заново). Повтори до зелёного, но не больше ~2–3
   кругов — упрямую проблему не лечи фикс-на-фиксом, останови и предложи откат. Блокеров
   нет -> скажи, что к коммиту готово (но сам не коммить без команды).

Если хочешь более глубокое ревью «свежими глазами» — делегируй субагенту code-reviewer.
Сам правки не вноси без моей команды; этот шаг — про оценку готовности к коммиту.
